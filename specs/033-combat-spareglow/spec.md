# 仕様書: 033-combat-spareglow（スペアグロウ — 余熱を持ち帰る篝火の闘技場）

- 作成日: 2026-11-01
- ステータス: PLAYABLE（v0.2.0、サイクル39・2回目でFIX: 熱の盾）
- 元になったレビュー: [reviews/032-flagship-propvent-final.md](../../reviews/032-flagship-propvent-final.md)（提案(1)「早めに引くが次の出撃を強くする」）
- 土台: [027-combat-emberstake](../027-combat-emberstake/spec.md) v0.3.0（熱のダイヤル・奉納・救助・踏ん張り）をそのまま使い、**余熱**の規則を1つだけ足す
- 要素: **戦闘（combat）単体**（採掘・建築は入れない）

## コアファン仮説（1行）

> このゲームは「HPに余裕を残して帰ると、その余裕が次の出撃の熱（＝報酬倍率）になる」ので、
> 「どこまで粘るか」だけでなく「どれだけ残して帰るか」を選ぶのが面白いはず。
> そして、早めに引く慎重な型が、加点ではなく**稼ぎそのもの**で上位に並ぶはず。

## 032からの引き継ぎと、この仕様で答える問い

- 032-final 新規重大#1: 「無傷の帰還」のscore加点は、全1440ランで score − 加点 = 加点なし と一致し、**行動を1つも変えなかった**。
  p02（早めに引く型）の順位が上がったのは採点表の上だけで、稼ぎは下から2番目のまま
- 032-final 中#2: 加点が帰還の回数に比例したため、「何か拾ったら一度入る」（約10秒に1回の出入り）が最適になりかけた
- この仕様の答え: **帰り方が次の出撃の始まりを変える**。奉納の瞬間の熱のうち、HPの余力に比例した分を次の出撃へ持ち越す（余熱）。
  - 点は足さない。scoreは027と同じ「累計奉納」＝稼ぎそのもの
  - 余熱は「熱」なので、報酬倍率と一緒に**被ダメージ倍率も持ち越す**（1本のダイヤルに長所と短所、027の型）
  - 熱は撃破でしか上がらないので、戦わずに出入りしても余熱は増えない。持ち越す量は**帰還の回数でなく、育てた熱×残したHP**に比例する
- 検証で答える問い（routine-state.md の合格線）:
  1. **補正なしでも**早めに引く型（p02）が総当たり中位以上・稼ぎも中位以上か（score＝稼ぎなので、scoreの順位がそのまま稼ぎの順位）
  2. 「score − 余熱による上乗せ」と余熱なし（`--tune carryFrac=0`）のscoreが**一致しない**こと（＝行動が変わった）
  3. bareが過半数で勝つ相手0（5条件×2組）
  4. reset 3秒の罰 −5%以内（5条件×2組）
  5. 1出撃の長さの分布（中央値・10秒以下の出撃の割合）で、単調な出入りが最適になっていないか（`sprinter`＝熱+15かHP85%で即帰る型を対照に置く）

## コンセプト

- ジャンル: 見下ろし2Dのアリーナ近接戦闘（ホード系）。円形の闘技場の中央に篝火（027と同じ）
- 1セッション: 10分（6000tick、10tps）で「夜明け」。スコアは累計奉納
- 参考: Vampire Survivors（自動湧きの群れ）、Hades（部屋ごとの報酬確定）、カードゲームの「次のターンへ持ち越すマナ」

## コアループ

1. 篝火から出て、湧き続ける敵を斬る。撃破ごとに残り火を拾い、熱が上がる（報酬 ×(1+熱/25)、被ダメ ×(1+(熱/45)²)）
2. 撃破が4秒途切れると熱は冷め始める
3. 篝火の中央で1.5秒の詠唱＝奉納: 残り火を確定、HP全快。**熱は0に戻らず、余熱を残す**:
   `次の出撃の熱 = 奉納時の熱 × 0.8 × 余力`、`余力 = clamp((HP割合 − 0.2) / 0.8, 0, 1)`
   - 例: 熱60・HP60%で帰る → 余力0.5 → 次は熱24から（報酬×1.96・被ダメ×1.28で始まる）
   - 例: 熱100・HP25%で帰る → 余力0.06 → 次は熱5から
4. 奉納済みの残り火で強化（刃・鎧・癒し・器）を買い、また出ていく
5. HP0 → 救助: 抱えた残り火と熱を全て失う（**余熱も0**）。篝火の中央でHP全快・2秒無敵
6. 1出撃に1度の踏ん張り（HP3割で押し返し＋被ダメ半分、027 v3）は残す。**v2: 6秒に延ばし、発動の瞬間に熱の半分を捨てて盾に換える（熱の盾）**

## システム仕様

### ワールド・敵・ショップ

027-combat-emberstake v0.3.0 と同じ（半径11の闘技場、篝火の上では斬れない、火を恐れる半径4、雑兵・走り屋・重兵、
時間で強化、多芸は高くつく（他の強化1種ごとに価格×1.8））。詳細は [027の仕様書](../027-combat-emberstake/spec.md)。

### 033で足すもの: 余熱（carry）

| 項目 | 値 | 意味 |
|---|---|---|
| `carryFrac` | 0.8 | 余力1（HP100%）のとき持ち越す熱の割合 |
| `carryFloor` | 0.2 | HP割合がこれ以下なら持ち越さない |
| 救助 | 0 | 倒れたら余熱も失う |
| 熱の冷め | 奉納直後は4秒の猶予（撃破したのと同じ扱い）、その後は撃破が途切れると冷める | 余熱は使わないと消える |

- HUD: 「今帰れば次の出撃は 熱N から（熱のX%を持ち越す）」を常時、「この出撃は熱Nから」を併記。奉納の表示に「余熱N で次へ」
- 指標（simulate）: 余熱の平均（`carry`）、奉納時のHP割合（`bankHp`）、余熱による上乗せの合計（`carryBanked`）、
  出撃の回数・長さの中央値（`medSec`）・10秒以下の出撃の割合（`short`）

### v2で足したもの: 熱の盾（v1重大#1 迷いの崖への対応）

| 項目 | 値 | 意味 |
|---|---|---|
| `graceShed` | 0.5 | 踏ん張りの発動の瞬間に捨てる熱の割合 |
| `graceShield` | 0.5 | 捨てた熱1につき盾（HPより先にダメージを吸う）0.5。盾は奉納・救助まで残る |
| `graceTicks` | 30→**60** | 踏ん張り（被ダメ半分）の長さ |

- 狙い: 余熱は「早く帰った人」だけを報いた（v1）。熱の盾は**帰り損ねた人**を救う。熱が半分になると被ダメージ倍率は凸なので大きく下がる（熱70: ×3.4 → 熱35: ×1.6）
- 代わり: 帰り道の撃破の報酬倍率が下がり、余熱の見込みも半分になる（HP3割を切った時点で余力は0.125なので元々小さい）
- 早めに帰る型（HP3割より上で帰る）は発動しないので、遅延0の強さはほぼ変わらない
- HUD: HPの横に「盾N」、自機に青い輪。発動の瞬間に「熱−N→盾M」の浮き文字

### ボットの帰る判断（033での変更）

- 027のボットは「熱がT以上」で帰ったが、余熱で出撃が熱0から始まらないため、**この出撃で熱がT以上上がったら**帰る（`bankHeat`は増分）
- HPの線（`bankHpFrac`）は027と同じ
- 迷い（反応遅延）は2種: `reset`（帰る条件が外れるたびに数え直す、027の既定）と `sum`（1出撃で迷うのは合計N回まで）

| 戦略 | 強化の順 | 帰る熱の増分 | 帰るHP | 狙い |
|---|---|---|---|---|
| p01 | 刃・鎧・刃・癒し・鎧・器 | +100 | 35% | P01: 攻防を交互、熱100まで |
| **p02** | 器・鎧・癒し・刃 | +40 | **60%** | P02: 早めに引く（027の50%から上げた） |
| bare | 刃のみ | +60 | 30% | 対照: 生存に投資しない攻勢 |
| noshop | なし | +50 | 40% | 対照: 何も買わない |
| tank / mender / even / duel / warden / banker / pusher | 027と同じ | | | |
| **sprinter** | 器・鎧・癒し・刃 | +15 | 85% | 対照: 単調な出入り（余熱を最大に保つ） |

## タッチ操作の想定（iPad/Android、Capacitor移植時）

- 左下の仮想スティック: 移動。右下の大ボタン: 斬る（押しっぱなしで連続）。大ボタンを外側へスワイプ: ダッシュ
- 篝火の上では大ボタンが「奉納」（長押し1.5秒、リング表示）に変わり、画面右に強化パネル（4つのタイル）
- **余熱の見込み**は篝火の方向を指す矢印の横に「帰れば熱N」と出す（HUDを読まなくても、帰る判断の瞬間に目に入る位置）
- 実装はキーボード（WASD・Space・Shift・B長押し・1〜4）。core は触らない

## バランス初期値

027 v0.3.0 の TUNE をそのまま使い、`carryFrac=0.8`・`carryFloor=0.2` を足した（v2で `graceShed=0.5`・`graceShield=0.5`・`graceTicks=60`。`--tune graceShed=0,graceTicks=30` でv1と同じ）。`--tune carryFrac=0` で 027 と同じ規則（熱0から）になる
（ボットの帰る判断と p02 のHP線だけが027と違う）。

## AI評価の観点

- 余熱なし（`carryFrac=0`）と並べ、score − 余熱の上乗せ が一致しない（行動が変わった）か。順位が上がった分のうち、行動の変化による分はどれだけか
- p02 が稼ぎで中位以上か。上がった分が「早めに引く」の報いか、単に出入りを増やした結果か（出撃の回数と長さを見る）
- sprinter（単調な出入り）が勝たないか。出撃の長さの中央値と10秒以下の割合
- 余熱の被ダメージ（熱を持ち越すと危ない所から始まる）が、攻める型の罰になりすぎていないか（救助の回数）
- 反応遅延3秒・6秒（sum/reset）の罰。027では遅延3秒で p01 −29%（踏ん張りで−79%から緩めた崖）だった
- bareが過半数で勝つ相手
