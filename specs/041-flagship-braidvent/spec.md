## 引き継いだ前提と、この仕様で答える問い

- 032〜039 の本命では、1位が spireAll（全基を梁なしで自由長の上限4まで）・pusher・weave に寄り、遅延0・3秒reset のどちらかで全勝の型が出ることが多かった（039-final: 遅延0 pusher 全勝、3秒reset spireAll 全勝）
- 040（建築単体）で、**地盤ごとの自由長の上限（岩5・土4・湿地3）**を入れると「梁なしの塔」が勝つ場所が限られた（9セル中2）。梁は「自由長を梁の高さから数え直す」と「歩兵を止める輪」の2役
- 039 の c（拠点の回復に時間・傷が深いほど遅い・救助の後HP5割）は慎重な型の帰る線を平らにした唯一の部品。a（救助費）・b（低HPで被ダメ増）は迷う攻める型の罰を重くするだけだった
- **この仕様の問い**: 本命の拠点の周りの区画に岩・土・湿地を置き、梁を「柵」にすると、spireAll（梁なし全基）の全勝は地盤の配置で崩れるか。039 の a・b を外しても p02 の順位と迷いの罰は保てるか
- 合格線（routine-state.md）:
  1. 全勝の型がいるセルが半分以下（「大差の全勝」＝全勝かつ1〜2位の差3%以上も併記）
  2. bare が過半数で勝つ相手 0
  3. p02 が 039 の80合計5位から下がらない
  4. 3秒reset の罰 −5% 以内
  5. `--preset 039` で 039 v0.3.0 と全フィールド一致

## コアファン仮説（1行）

> このゲームは「拠点の区画ごとに梁なしで積める高さ（岩5・土4・湿地3）が違い、梁で編むと上限を数え直せて、しかも夜のレイダーを拠点の手前で止める柵になる」ので、
> 「固い区画は梁なしで高く、柔らかい区画は梁で編んで柵にする」を拠点ごとに読むのが面白いはず。

## コンセプト

- 039と同じ: 横長の坑道フィールド（左端がホーム、幅320×5レーン）、昼は掘って戦って持ち帰る遠征、夜はレイダーから拠点と塔を守る。1ラン20000tick（10tps）
- 参考: 城づくりゲームの「地盤で建てられる物が変わる」、タワーディフェンスの「壁で敵を止めて砲台で撃つ」

## コアループ

1. 039と同じ遠征（掘る・戦う・割れ目・支柱・固めた坑道を走る・重兵の予兆を読む・帰る）。拠点の回復は c だけ（a・b は外した）
2. 拠点に塔を建てる時、**その区画（レーン）の地盤を見る**。左端の絵と数字（岩5・土4・湿地3）が梁なしで積める自由長の上限
3. 上限を超えて積むと折れうる（039と同じ）。**梁で隣の塔と編むと自由長は梁の高さから数え直し**（039と同じ）、さらに**梁で編んだ塔群は拠点圏の境目に柵を張る**
4. 夜、柵の張られたレーンでは、レイダーは拠点圏へ踏み込めず柵の外で止まり、梁を叩く（橙の輪）。梁が折れると柵は1段下の梁へ下がり、全部折れると柵が消え、梁の下にあった塔は自由長が伸びて折れうる
5. **柵の無いレーンから拠点に着いたレイダーは、1打ごとに所持金を荒らす**（040 の plunder。柵の値打ち）

## システム仕様

| 規則 | 内容 | 調整値（TUNE、v0.1.0の既定） | `--preset 039` |
|---|---|---|---|
| 039 の整理 | a（救助費 `rescueBankMult`）を外す。b（低HPで被ダメ増 `hpDmgLow`）は v0.1.0 で外したが pusher が全勝したので **v0.2.0 で半分の 0.75 に弱めて戻す**。c（`baseRegen 2`・`healKnee 0.8`・`rescueHp 0.5`）は残す | `rescueBankMult 0`・`hpDmgLow 0.75`（v0.1.0 は 0） | 0.5・1.5 |
| 地盤（区画） | 拠点ごと×レーンごとの地盤。0＝全部土（上限4＝039）、1＝混在（シード・拠点のx・レーンのハッシュで岩・土・湿地。乱数の列は消費しない）、2＝全部岩、3＝全部湿地、4＝縞（レーン0,4 岩・1,3 土・2 湿地） | `groundMode 1`、`slenderRock 5`・`slenderSoil 4`・`slenderMarsh 3` | 0 |
| 自由長の上限 | 塔ごとの上限＝その塔の区画の地盤（039 は全塔共通の4）。折れる式（超過×確率、折れると「最高の梁＋上限」まで落ちる）は039と同じ | — | 4 |
| 梁の柵（梁の2役目） | 梁で繋がった塔群の回廊のレーン（最小〜最大）±`beamWallReach` で、夜のレイダーは拠点圏の外から中へ踏み込めない。止まったレイダーはその群の最も高い梁を叩く（プレイヤーが手の届く所にいればプレイヤーが先）。止まっている間は拠点を削らない | `beamWall 1`・`beamWallReach 1` | 0 |
| 梁の耐久 | 12＋`beamHpPerLevel`×梁の高さ（柵として叩かれるので高い梁ほど固い） | `beamHpPerLevel 3` | 0（12固定） |
| 柵の杭（v0.2.0） | 柵で止められたレイダーは梁ではなく杭（梁ごとの別の耐久＝梁の耐久と同じ値）を叩く。杭が尽きるとその梁の柵だけ開き（次に高い梁の柵が前に出る）、梁は折れず塔は崩れない。杭は夜明けに戻る。0で v0.1.0（梁を叩き、折れると塔が崩れうる） | `wallStakes 1` | 0 |
| 不在の荒らし（v0.2.0、候補・無効） | その拠点圏にプレイヤーがいない打撃だけ荒らしを ×`raidAbsentMult`。80シードで p02 も同じだけ重くなったので不採用 | `raidAbsentMult 1` | 1 |
| 拠点にいる時の荒らし（v0.3.0、候補・無効） | その拠点圏にプレイヤーがいる打撃の荒らしを ×`raidHomeMult`（「拠点で待つ」守りの値打ち）。10シードで 0.5・0 を比べ、全員の荒らしが減って p02 の順位は上がらず（p02 は夜に前線や帰り道にいる時間が長い）不採用 | `raidHomeMult 1` | 1 |
| 荒らし | 拠点に着いたレイダーの1打で、所持金から 打撃×`raidPlunder` を失う（0未満にはしない、score は所持金を含むので score も減る） | `raidPlunder 1` | 0 |

- **ボット p02 の小さな柵（v0.3.0、simulate 側）**: p02（あき型）は昼に拠点で、その拠点の最初の2基を高さ `--p02Fence`（既定4、地盤の上限まで）に積み、2基を梁で編む（梁なしの上限を超えない低い塔＋梁1本＝柵の得だけを取る）。`--p02Fence 0` で v0.2.0 の p02（塔を積まない）。`--preset` を付けた時は0。規則は変えない（ボットの比較）
- 点は足さない。score の式は039のまま（荒らしは所持金から引くだけ）
- **`--preset 039`（`?preset=039`）で 039 v0.3.0 と同じ規則**。9戦略の一部（weave・spireAll・p02 × シード1〜2）で 039 と score・全指標が一致することを確認済み（v1レビュー）

### HUD・絵

- 拠点圏をレーンごとに地盤の色で薄く塗り（岩＝灰・土＝茶・湿地＝青緑）、左端に地盤の絵と上限の数字
- 梁の柵: 拠点圏の境目に杭の列（杭の耐久が減るほど橙→赤、尽きると消える）。止められたレイダーは橙の輪。3行目に「杭が尽きたN」（v0.2.0）
- 3行目に「荒らされ¥N 柵で止めたN」、4行目の塔の欄に「塔#N(湿地) h3 自由長3/3」
- 凡例に「岩の区画(上限5)・土の区画(4)・湿地の区画(3)・梁の柵」を足す

### 検証ボット

- 039 の9戦略（pusher・spireAll・p01・weave・p02・mason・wall・spire・bare（対照））。帰還線・帰るHP・出発の線（departHp 0.7）は039のまま

- セル: 地盤の配置（混在・全部岩・全部湿地・全部土）×（遅延0・3秒reset）、比較に `--preset 039` と `beamWall=0`
- simulate に `--cell <名前>` を足した（040 の要約の移植）: 1位・2位・1〜2位の差・全勝・大差の全勝・bare が勝ち越す相手、柵の指標（止めた延べ数・叩いた回数・止めた秒・荒らされた額・塔の終わりの高さ）を1行の JSON（`{"cell":...}`）で出す

## AI評価の観点

- 039 からの回帰: p02 の順位、3秒reset の罰、bare が勝つ相手
