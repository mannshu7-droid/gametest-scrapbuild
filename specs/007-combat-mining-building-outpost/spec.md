## コアファン仮説（1行）

> 深部で「前線基地（アウトポスト）」を建てると、そこが新しい地上（帰還先・ショップ・回復地点）になり、
> 「基地があるからもう少し深く行けそうだ」という具体的な次の一手が採掘のたびに繰り返し生まれる———
> 002〜006を通じて一度も解決されなかった「壁を超えた先に新しい目標が生えない」問題が、
> 「目標そのものを生む建築」によって本質的に解消されるはず。

## コンセプト

- ジャンル / 視点: 縦シャフト採掘 + リアルタイム近接戦闘 + 設置建築（2Dトップダウン、003/005/006を踏襲した縦シャフト視点）
- プレイ時間の想定: 1セッション10〜20分（005/006を踏襲）
- 参考にするゲーム: 7 Days to Die（拠点の再配置による行動範囲の拡張）、Terraria（前線拠点からの再出発）、
  および本リポジトリの003（帰還デザイン）/005（常設ショップ）/006（迂回橋・バリケード）

## コアループ

```
地上または前線基地(常設ショップ)で採掘・戦闘・建築を強化
  → 坑道を掘り進む（鉱石獲得、掘削音が敵を誘発）。硬いタイルは迂回橋で、退路の脅威はバリケードで対処する（006を踏襲）
  → 「前線基地から一定以上深く進めた」ら、その場に前線基地を建てるか判断する
    （建てれば以後の帰還・ショップ・回復がここを起点になり、往復コストが劇的に下がる。建てなければ現金を温存できる）
  → 燃料・HPが危険域に入る前に最寄りの基地（地上 or 前線基地）へ帰還
  → 鉱石を売却し、稼いだ金で採掘/戦闘/建築のどれに投資するか、次の前線基地の建設費として温存するかを選ぶ
  → 前線基地が新しい「そこそこ近い地上」になったことで、次の目標（もう一段深く・次の基地を建てる）が
    具体的な距離感を伴って見える → さらに深く
```

## タッチ操作の想定（iPad/Android移植時。今回の実装はキーボードでよい）

- 移動・採掘: 画面下部の仮想8方向パッド（005/006と同じ。既に掘った床なら移動、未採掘タイルなら採掘）
- 攻撃 / スキル: 独立ボタン2つ（005/006を踏襲）
- 緊急離脱（dash） / 支保工設置（build）: 独立ボタン2つ（006を踏襲）
- **前線基地の建設（outpost）**: 新規の第6ボタン。現在立っている床タイルに前線基地を建てられる状況
  （直前の基地から十分深く、かつ費用を払える）でのみ有効化され、押すと即座に建設される
  （方向指定不要、対象は常に自分の足元）
- HUDには「直前の基地からの深さ」「次の基地を建てられるまでの残り深さ」「建設費用」を常時表示し、
  次の目標までの距離が一目で分かるようにする（003のestFuelToReturnパターンの応用）
- ショップ: 地上または前線基地に滞在中のみ画面全体にカテゴリ一覧を表示、タップで購入
  （PC版のキー1〜9に対応。9番目が建築枠、0番目相当が前線基地建設）

## システム仕様

### ワールド

- 縦シャフト構造（003/005/006を踏襲）: 幅 `W=16`、深さ `H=161`（y=0が地上、y=1〜160が8バンド×20マス）
- タイル種別: `FLOOR` / `DIRT` / `ROCK` / `ORE_COPPER` / `ORE_IRON` / `ORE_GOLD` / `PROP`（006と同一）に加え、
  新規 `OUTPOST`（前線基地。プレイヤーが設置した恒久構造物。移動威力に関係なく常に通行可能で、破壊されない）
- `OUTPOST` は`PROP`と異なり耐久値を持たず、敵の攻撃で壊れない（拠点としての安全性を保証するため）。
  かわりに`PROP`（迂回橋・バリケード）より遥かに高コストで、設置に深さの間隔制約がある（後述）
- `OUTPOST` を中心に半径2マス（チェビシェフ距離）は地上の`SAFE_ZONE_Y`と同格の安全圏になり、
  敵の湧き・侵入を禁止する（固定範囲の保護装置パターンの深部への拡張）

### プレイヤー（能力・リソース・成長）

- HP・燃料・所持金・積載・採掘威力・攻撃力・攻撃CD・スキル・掘削音・dash・支保工設置: 006を全て踏襲
- **outpost（前線基地の建設）**: 新規アクション（方向指定なし）。以下すべてを満たすときのみ発動する
  - 現在地が`FLOOR`タイル（既に掘った床）であること（未採掘タイル上には建てられない）
  - 直前に確立した基地（地上 or 最も新しく建てた前線基地）から、深さ方向に`OUTPOST_MIN_GAP`マス以上
    離れていること（間隔制約。深さが足りないと建設不可）
  - 所持金が建設コスト以上あること
  - 発動すると: 現在タイルを`OUTPOST`に変更し、所持金からコストを消費し、その場で「基地に到着」した扱いになる
    （積載中の鉱石を売却・所持金に加算、燃料全回復、`phase`が`shop`になりその場でショップ購入が可能）
- **estBaseDistance**: 「既に掘った床・支保工だけを通って**最寄りの基地（地上 or 前線基地のいずれか近い方）**へ
  戻るのに必要なBFS距離」に一般化する（003/005/006の`estFuelToReturn`を前線基地対応に拡張）。
  前線基地を建てた直後にこの数値が大きく下がることで「基地を建てる価値」が数値として即座に体感できる
- **depthSinceLastBase**: 直前の基地からの深さ（プレイヤーのy座標 − 直前の基地のy座標）。
  `OUTPOST_MIN_GAP`との比較で「次の基地まであと何マス」が分かる

### 敵（種類・行動・スポーン）

- 種別・湧き確率・BFS移動・囲みスロット割当て・支保工への攻撃: 006を完全に踏襲
- 追加: 敵の`isEnemyFloor`判定は、既存の地上安全圏（y<=2）に加えて**前線基地の半径2マス以内**でも false になる
  （安全圏が複数箇所に分散する）。前線基地の`OUTPOST`タイル自体は`PROP`と同様に敵にとって常に通行不可

### 経済（資源の入手と使い道の対応表）

006の常設ショップ9項目（drill/capacity/fuel/atk/hp/atkspeed/skill/muffler/engineering）はそのまま踏襲する。
前線基地の建設は「購入」ではなく専用アクションだが、経済的には最大の投資先として並列に位置づける。

| 項目 | 内容 | 備考 |
|---|---|---|
| 前線基地の建設コスト | `round(OUTPOST_BASE_COST × (1 + band × OUTPOST_BAND_COST_MULT))` | bandは建設地点の深さバンド。深いほど高額 |
| 前線基地の建設間隔 | `OUTPOST_MIN_GAP` マス（深さ方向） | 連続して建てられず、必ず一定距離を掘り進んでから次を建てる |
| 前線基地での購入 | 地上ショップと完全に同一の9項目・同一価格 | 「常設・複数カテゴリショップ」パターンを基地に複製する |

### 勝利/敗北条件

- 敗北: HPが0になる（ゲームオーバー）。005/006と同様、単一の到達目標では終了しない
- スコア = 所持金+積載中価値 + maxDepth×係数 + 撃破数×係数 + 前線基地建設数×係数
  （006は建設自体を得点化しなかったが、007では「基地を建てて前進を続けたこと」自体が中核仮説の検証対象のため、
  小さめの得点を加える。ただし主評価はmaxDepth・生存・スコアの伸びで行う）

## バランス初期値

| 項目 | 初期値 |
|---|---|
| 005/006由来の全項目 | reviews/006-combat-mining-building-ironkeep-final.md 時点の最終値をそのまま継承 |
| OUTPOST_MIN_GAP（建設間隔） | 25マス（1.25バンド相当。最初の基地は地上からy=25以降で建設可能） |
| OUTPOST_BASE_COST | 150 |
| OUTPOST_BAND_COST_MULT | 0.35（band1で+35%、band4で+140%…と深いほど加速度的に高くなる） |
| 前線基地の安全圏半径 | 2マス（チェビシェフ距離、地上のSAFE_ZONE_Yと同格） |

これらは初期仮説値であり、`npm run simulate` の結果を見てv1レビューまでに調整する。
特に「建設コストが高すぎて誰も建てない」「安すぎて連発できてしまい間隔制約が無意味になる」の
両極端を避けることを最優先で検証する。

### 実装中に判明したバランス調整

ヘッドレスシミュレーション実装中に、初期仮説値OUTPOST_BASE_COST=150が「実質建てられない」水準の
過大な設定だったことが判明した。この経済規模（20000tick全体での総稼得金は70〜120程度）に対し¥150は
数トリップでは到底届かず、さらにボットの「建設費用を貯めるために全ての通常購入を停止する」という
素朴な予約ロジックと組み合わさることで、通常のステータス購入すら一切できなくなり成長が完全に止まる
「貧困の罠」を引き起こした（全戦略でavgUpgradesBought=avgOutposts=0に固着）。OUTPOST_BASE_COSTを
150→**50**へ引き下げ、ボットの予約ロジックも「深さ条件を満たした瞬間に全額予約」から「既にコストの
4割以上貯まってから予約を始める」ヒステリシス方式に変更して解消した。ただし¥50へ引き下げた後も
なお経済ペースに対して重く、v1レビュー（reviews/007-combat-mining-building-outpost-v1.md）の時点で
「1セッション(6000tick)ではP01・P02とも前線基地を1本も建てられない」という重大な指摘が残っている。

### v2 FIX内容（reviews/007-combat-mining-building-outpost-v2.md）

v1指摘バグ#2（建設費用と経済規模の乖離）・#3（壁直前建設による停滞固定化）に対応した。

| 項目 | v1 | v2 |
|---|---|---|
| OUTPOST_BASE_COST | 50 | **20** |
| OUTPOST_BAND_COST_MULT | 0.35 | **0.15** |

加えて、`canBuildOutpost()`に「建設費用を払った後の所持金でも、1つ下の行(次のband)全16列が採掘威力・
迂回橋のいずれでも一切突破できない完全な壁でないか」を確認する`hasForwardProgressBelow()`チェックを
追加した（理論上絶対に詰む配置を防ぐ安全網）。ヘッドレスボット（`headless/simulate.ts`）には2点の修正を
入れた: (1) 予約額の再計算が`phase==='mine'`のときだけに限定されていたため、基地到着直後の大口売却益が
そのまま通常購入に溶けてしまうバグを修正（毎tick再計算するよう変更）、(2) 「1つ下の行」を見て壁を検知し
迂回橋代を優先確保する`wallReserve`を追加。結果、ヘッドレス20シードでavgOutposts0.8→1.4、
avgMaxDepth58.3→71.1（mining-first）まで改善し、ブラウザAIPのP01/P02双方で初めて前線基地の建設に
成功した。ただし、band境界の壁のすぐ隣で小刻みな往復を続ける軽度の停滞パターンが一部残存しており
（combat-first戦略・P02ブラウザセッションで確認）、詳細と今後の対応方針はv2レビューのLearningsを参照。

## AI評価の観点

- **前線基地は実際に建てられるか**: drill投資を優先する戦略・戦闘投資を優先する戦略のいずれでも、
  「次の基地を建てるための貯金」が自然に選ばれる場面が生まれるか（一度も建てられなければ致命的な設計失敗）
- **前線基地は「新しい目標」を生んでいるか**: 基地を建てた直後、プレイヤー（bot）の行動が
  「次の基地までの距離」を意識したものに変化しているか（005final/006finalで指摘された
  「壁到達後に次の目標が生まれない」問題が、定性的に解消されているかをブラウザAIPで確認する）
- **プレイスタイル依存を避けられているか**: 006final提案4「迂回橋がefficiency優先プレイでほぼ使われない」
  問題の再発を避けるため、前線基地の価値（往復コスト削減）がdrill優先・atk優先どちらの戦略でも
  等しく発生するか（往復コストは戦略によらずBFS距離で決まるため理論上は等しいはずだが、実測で確認する）
- 前線基地の建設コストが「建てるか、ステータス強化に回すか」で悩ましいトレードオフとして機能しているか
  （自明にどちらかが正解になっていないか）
- 006で確立した迂回橋・バリケードの使用頻度が、前線基地の追加によって悪化していないか（役割が競合しないか）

## スコープ外（今回は作らないもの）

- 前線基地の複数種類・カスタマイズ（防御力強化・自動採掘等）: 「補強構造物1種類」の006の方針を踏襲し、
  前線基地も1種類の最小構成に絞る
- 前線基地の破棄・移動・売却: 一度建てたら固定。管理の複雑化を避ける
- 前線基地間のワープ（瞬間移動）: 「歩いて戻る距離が縮む」までに留め、瞬間移動は今回のスコープ外
  （BFS距離が0になるような過剰な利便性は、006最終レビューが指摘した「安全側バランスの継承→
  検証のための難易度引き上げ」の二の舞になりかねないため、まずは距離短縮効果だけで検証する）
- 環境ハザードタイル（ガス・崩落）: 005から継続してスコープ外
- マルチプレイ: 将来のスコープ
