## サイクル17の狙い

010-combat-building-bastionのfinalレビューが提案した通り、**「採掘」要素は003-mining-deepvein
（サイクル2）以来009・010の2サイクル連続で意図的に除外されており、009・010で確立した
「横方向帯状フィールド構造（x=進行度0〜320、y=5レーン）」への移植性検証が採掘だけ未実施**という
指摘を受け、本サイクルでは**採掘単体を009/010と同じ横方向帯状フィールド構造に載せ替える**
検証を行う。003は「幅16×深さ160の縦シャフト」という固定空間構造の上に採掘の全システム
（ドリル威力ゲート・燃料/積載管理・地形由来の危険・常設ショップ）を確立したが、009が
戦闘由来9パターン、010が建築由来2パターンについて行った「空間構造を変えても機能するか」の
検証を、採掘についても対で行うことで、要素ローテーションの最後のピースを埋める
（戦闘=3回検証済み、建築=5回検証済み、採掘=003の1回のみ、という不均衡の解消）。

## コアファン仮説（1行）

> 003で確立した「掘って稼いで強化し、より深く・より速く進めるようになる」という
> **稼ぐ→使う→楽になる→もっと稼げる**の循環は、縦シャフトではなく009/010と同じ横方向の
> 帯状フィールド（幅5レーン×長さ320マス）に移植しても、同じ強さで機能するはず。

## コンセプト

- ジャンル / 視点: 2Dトップダウン、タイルベースの採掘×資源経済（003の直系）。戦闘・建築要素は
  一切なし（CLAUDE.mdの「1ゲーム=1要素」規約を厳守。005〜010の組み合わせ試作とは異なり、
  本サイクルは要素ローテーション上「単一要素の空間構造移植性検証」に専念する）
- 空間構造: 009/010を踏襲する横に長い帯状フィールド（**幅5レーン(y=0〜4)×長さ321マス(x=0〜320)**）。
  x=0列（5マス）がホーム（既に掘られた床・保護地帯・ショップ）。x=1〜320は未採掘で埋まっており、
  右へ進むほど（band=`floor((x-1)/40)`、8バンド）岩が硬く危険タイルが増える——003の「深さ」を
  そのまま「x方向の進行距離」に置き換えた構造
- プレイ時間の想定: 1セッション10〜20分（003と同じくHPが尽きるまでのエンドレス・スコアアタック。
  009/010のような「到達すればクリア」の勝利条件は採用しない——採掘由来パターンの検証が目的であり、
  勝利条件の移植性は対象外とする）
- 参考にするゲーム: 003-mining-deepvein（採掘の全システム）、009-combat-ironmarch/
  010-combat-building-bastion（横方向帯状フィールドの空間構造・band概念）

## コアループ

ホーム（x=0）でショップ強化を買う → 右へ掘り進みながら鉱石を集める（燃料・HP・積載量を
消費しながら、5レーンを上下に使って硬い岩や危険タイルを迂回する） → 燃料切れ・積載満杯・
危険を感じたらホームへ帰還（既に掘った床を辿って自動換金＋燃料全回復） → 稼いだ金で
ドリル威力・燃料・HP等を強化 → さらに遠く・効率よく進めるようになる → … →
HPが0になったら終了（スコアは金・到達距離・採掘数から算出）。

## システム仕様

### ワールド

- 帯状フィールド: 幅(y)=0〜4の5レーン、長さ(x)=0〜320
- x=0列（5マス）: ホーム（既掘の床。保護地帯＝危険タイルなし・ショップ利用可）
- x=1〜320: procedural生成された未採掘タイル（土/岩/銅鉱石/鉄鉱石/金鉱石/ガス溜まり/崩落岩）で
  埋まっている。**一度掘った通路は永続**——帰り道は必ず自分の掘った床を通ってホームへ戻れる
  （003を踏襲、BFSでの経路詰みは構造上発生しない）
- band = `floor((x-1)/40)`（8バンド、x=1〜40がband0、…、x=281〜320がband7）。009/010の
  band概念（`floor(x/40)`）をオフセット1（x=0はホーム専用）で踏襲し、003のタイル難度カーブ
  （`requiredDrillPower`・`digTicksFor`・`oreValue`・`pickTileType`）をband入力だけ差し替えて
  そのまま流用する

### プレイヤー（能力・リソース・成長）

- HP・燃料・積載量・ドリル威力・採掘速度Lv・ランタン(燃料効率)Lv・危険耐性Lv・
  地上テレポート解禁（003と同一の8ステータス体系）
- 移動: 4方向（left/right=x方向の進退、up/down=y方向のレーン変更）。既に掘った床なら即移動、
  未採掘タイルなら採掘を開始/継続する（ドリル威力不足なら不発、複数tick要する場合あり）。
  5レーンの上下移動は、003の16マス幅での左右移動に相当する「硬い岩・危険タイルを迂回する」
  戦術的選択の役割を担う——16レーンから5レーンへの縮小が、009/010と同格の「レーン選択」の
  悩ましさとして機能するかを検証する
- **安全マージンの数値公開**（008パターン#2、003で確立）: `estFuelToReturn`
  （既に掘った床経由でホームへ戻るのに必要な推定燃料、BFS距離×消費率）をそのまま踏襲する
- **危険度UIヒント（新規、009/010パターンの採掘への移植テスト）**: `miningRiskLevel`
  （'safe'/'caution'/'danger'）を新設する。`fuel <= estFuelToReturn + 15`なら'danger'、
  `fuel <= estFuelToReturn * 1.8`なら'caution'、それ以外は'safe'。003にはこの3値ヒートマップは
  存在せず、生の数値（estFuelToReturn）のみだった。009/010で確立した「危険度を色分けで直感的に
  示す」パターンを採掘の燃料管理に初めて適用し、生数値だけの003版と比べて意思決定を助けるかを
  比較評価する
- **危険度再悪化のたびのHUDハイライト**（008パターン#11、009/010で確立）: miningRiskLevelが
  一度改善した後に再び悪化するたびに、`riskEscalationBanner`（90tickハイライト）を立てる
- **常時使用可能な緊急脱出は今回あえて採用しない**: 008パターン#5「常時使用可能な緊急離脱」は
  010では購入不要のdashだったが、003の地上テレポートは「ショップで150金を払い1回だけ解禁する」
  設計だった。本ゲームでもテレポートは003を踏襲し**解禁制のまま**とする——これは提案からの
  意図的な逸脱ではなく、「いつでも安全地帯に戻れる」を最初から無料にすると003のコア仮説である
  燃料管理の緊張（estFuelToReturn/miningRiskLevelを見ながらギリギリまで進む判断）自体が
  消えてしまうため。この設計判断の妥当性をAI評価の観点で検証する
- **タイルごとの掘削進捗の永続化（v2追加）**: `estFuelToReturn`の危険域境界で撤退すると、
  v1では掘削中タイルの進捗が`digging=null`で完全に破棄され、境界のすぐ先を永久に掘り切れない
  無限ループ（reviews/011-mining-driftline-v1.md 致命バグ#1）が発生した。v2では中断時の
  残りtickをタイルごとに永続化し、次回同じタイルに戻れば残りから再開できるようにした
- **「詰みからの脱出手段」（v2追加、008パターン#4／010 v2の移植）**: ホーム滞在中、未購入の
  強化のうち最も安いものすら買えない資金しかない間だけ、少額の収入（25tickごとに2金）が
  入るようにした。安全マージンに起因する到達距離の物理的な上限（進むほど帰還コストも同じ
  速度で増える構造）は掘削進捗の永続化だけでは解消できず、装備強化（特に燃料タンク）の
  原資を保証する必要があると判明したための追加

### 経済（資源の入手と使い道の対応表）

| 資源/収入 | 入手方法 | 使い道 |
|---|---|---|
| 銅鉱石・鉄鉱石・金鉱石 | 掘って積み荷にする。bandが進むほど基礎価値・出現率が上昇 | ホーム帰還で自動換金 → 金に変わる |
| 金 | 換金で入手 | ドリル威力／燃料上限／HP上限／積載量／採掘速度／燃料効率(ランタン)／危険耐性／
  ホームテレポート解禁 の8カテゴリに投資（003と同一） |

**常設・レベル制の複数カテゴリショップ**（003で確立、008パターンとしても採用済み）をそのまま踏襲する。

### 危険（敵の代わりとなる障害）

- ガス溜まり・崩落岩（003と同一の定義・確率カーブ、band入力のみx由来に差し替え）
- 深いband（=xが大きい）ほど出現率が上がる。危険耐性強化で被ダメージを軽減する

### 勝利/敗北条件

- 敗北: プレイヤーHPが0
- 勝利条件は無し（003と同じくエンドレス・スコアアタック。009/010の「到達でクリア」は採用しない
  ——本サイクルの検証対象は採掘由来パターンの移植性であり、勝利条件の移植性ではないため）

## バランス初期値

003の数値をそのままband入力の差し替えだけで移植する（v1時点、変更が必要ならv2以降で調整）。

| 項目 | 初期値 |
|---|---|
| フィールド | 幅(y)5レーン × 長さ(x) 0〜320（x=0がホーム、x=1〜320が採掘可能領域） |
| バンド | `floor((x-1)/40)`（8バンド、x=1〜320） |
| 初期HP / 初期最大燃料 / 初期積載量 / 初期ドリル威力 | 100 / 100 / 20 / 1 |
| 燃料の毎ティック消費（受動） | 1（ランタン強化で軽減、下限-20%） |
| 採掘1ティックあたりの追加燃料消費 | 1 |
| 燃料0時のHPダメージ（毎ティック） | 1.5 |
| 危険タイル基礎ダメージ | `12 + band×2`（危険耐性で-15%/Lv、下限-45%） |
| ガス溜まり被弾時の追加燃料消費 | 15 |
| 崩落岩の発動確率 | 35% |
| 鉱石基礎価値（銅/鉄/金） | 7 / 22 / 54（`× (1 + band×0.12)`） |
| miningRiskLevel danger閾値 | `fuel <= estFuelToReturn + 15` |
| miningRiskLevel caution閾値 | `fuel <= estFuelToReturn × 1.8` |
| リスク再悪化ハイライト表示時間 | 90tick |
| tick rate | 10tps |

タイル要求ドリル威力・掘削時間・鉱石出現率カーブ・ショップ8カテゴリのコスト/成長率/上限レベルは
003と完全同一の式を使う（`requiredDrillPower(type, band)` / `digTicksFor` / `pickTileType(band, rng)` /
`SHOP_DEFS`、実装は`src/core/game.ts`を正とする）。数値そのものの再チューニングは本サイクルの
目的ではない（構造移植性の検証が主眼のため）。

## AI評価の観点

- **空間構造移植性の検証（今回の最重要観点）**: 003で確立した4つの主要パターン——
  (1) 常設・複数カテゴリショップ、(2) 安全マージンの数値公開(estFuelToReturn)、
  (3) 予兆ありのハード進行ゲート(ドリル威力)、(4) 地形由来の危険だけで成立する難易度——が、
  16マス幅×160マス深さの縦シャフトから5レーン×320マスの横帯状フィールドに変えても
  同じように機能するか。003 final Learningsが「本命ゲームの強化システムの土台」「他要素にも
  即座に転用できる」と結論づけたこれらのパターンが、実際に別の空間構造でも定量的に
  裏付けられるかを確認する
- **5レーンへの縮小の影響**: 003の16マス幅での左右移動（迂回・探索）が、5レーンでも同等の
  戦術的選択として機能するか。レーン数が少なすぎて「迂回する余地がない」詰みが生まれていないか
- **miningRiskLevel（新規UIヒント）がestFuelToReturnの生数値だけの場合と比べて有効か**:
  009/010の危険度ヒントパターンを初めて採掘の燃料管理に適用した効果を検証する
- **テレポート解禁制を維持したことの妥当性**: 008パターン#5（常時無料の緊急離脱）を採用しない
  意図的な設計判断が、理不尽な燃料切れ死を生んでいないか（003 finalの知見どおり
  estFuelToReturnベースの判断で十分機能するはずだが、5レーン×320マスという新しい距離感で
  再確認する）
- 003 final Learningsの標準チェック: **ヘッドレスbot・AIPスクリプトの移動ロジックが
  「未採掘の資源を優先する」など十分賢いか**を先に疑ってから、指標が悪ければゲーム側の
  パラメータを疑う（購入回数の目標未達を経済パラメータのせいにする前に、bot側の探索精度を疑う）
- 009-final/010-final Learningsの標準チェック: **単一シードのmaxTicksフル実行チェック**で
  over=falseのまま停滞するソフトロックがないかを確認する

## タッチ操作の想定（iPad/Android、Capacitor移植前提）

- 実装は既存ゲーム群と同様キーボードでよい（core/render分離を維持すれば移植時にタッチ入力を
  追加するだけで済む）
- 移植時の想定: 画面下部に仮想D-pad（4方向、x/y移動＝そのまま採掘/移動アクション）、
  右下に「テレポート」ボタン（解禁後のみ活性化）。ホーム滞在中は画面下部に8カテゴリの
  購入ボタン一覧を表示しタップで購入（003・008系のtouchInput.tsと同様のDOMオーバーレイ方式）
