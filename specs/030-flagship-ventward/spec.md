## コアファン仮説（1行）

> 昼の遠征で帰着線が注意線を越えている間、**塔の見張りの下でだけ**近くの壁に数秒の割れ目が開き、掘ると揺れが抜けるなら、
> 慎重な人が数秒迷って線を越えても「光る割れ目を取って落ち着く」ことで損が小さくなり、迷いの罰が慎重な側に偏る問題（028新規重大#1）が消える。
> 割れ目を塔の見張りに結ぶので、塔に投資しない攻勢（bare）は逃げ道を持たず、028の「bareが過半数で勝つ相手が無い」に近づく。

## コンセプト

- ジャンル / 視点: 2D横スクロール（上から見たレーン帯）、戦闘×採掘×建築＋昼夜サイクル防衛（本命ゲーム統合フェーズ・第十三世代）
- プレイ時間の想定: 1セッション20〜35分（20000tick、10tick/秒）。028と同一
- 参考にするゲーム: 028-flagship-haulward（ベース。全システムを継承）、029-mining-riftseam（割れ目・圧の逃げ道の移植元）

## コアループ

028と同じ（昼に採掘・戦闘で稼ぐ→拠点で強化・タレット・塔→夜にレイダーを防衛）。変わるのは「注意線の外で何が起きるか」:

- 帰着線（帰り道で揺れが最も高くなる見積もり、ゲージの白線）が注意線30を越えると、塔の見張りの下にいる間だけ、近くの掘った道に面した壁が**紫に光る割れ目**になる
- 割れ目は4秒で閉じる。1tickで掘れ（ドリル威力不要）、積荷に1つ乗り、**掘ると揺れが10抜ける**
- 「もう帰る時間だ」と思った時に隣で割れ目が光れば、取ると揺れが下がってもう少し居られる。取りに行くほど遠くへは行かない（4秒・4マス以内）

## システム仕様

028の全システムを継承する。調整値は`TUNE`（core/game.ts）にまとめ、`--tune key=value`で上書きできる。
**`--preset 028`（ブラウザは`?preset=028`）で028 v0.3.0と同じ規則**になり、028の出力と完全一致する（9戦略×3シードの全フィールドで確認）。
`--preset 026`も残る（026の救助＋割れ目なし）。

| 項目 | 式・値 | TUNE（028に戻す値） |
|---|---|---|
| 割れ目が開く条件 | 昼・拠点の外・帰着線≥注意線（30）・積荷に空き・**塔の見張りの下**（拠点圏・塔のパトロール圏・その遠征で圏を通った後＝028の防具と同じ条件） | `rifts=1`（0）・`riftTower=1` |
| 開く確率 | 1tickに riftChanceBase＋0.002×(帰着線−30)、同時に2つまで | `riftChanceBase=0.08`・`riftChancePer=0.002`・`riftMax=2` |
| 開く場所 | プレイヤーからマンハッタン距離4以内の、掘った道に面した掘れる壁（拠点圏の中は除く） | `riftRange=4` |
| 寿命 | 40tick（4秒）で閉じて元の岩に戻る | `riftLife=40` |
| 掘る | 1tick（ドリル威力不要）。積荷に1つ乗る（満杯なら乗らない） | - |
| 売値 | 深さだけ: 35×(1＋バンド×0.12)。揺れボーナスは乗らない（029 v2の「越えるほど高い」は迷いを先へ誘ったので使わない） | `riftBase=35`・`riftBandMult=0.12` |
| 圧の逃げ道 | 掘ると揺れが10抜ける | `riftRelief=10` |
| スコア | 掘った割れ目1つにつき+2（鉱石と同じ。割れ目が鉱石の枠を取るぶん鉱石のスコアが減るのを打ち消す） | （028では割れ目0なので同じ） |
| 割れ目の乱数 | 専用のPRNG（seed^0x5bd1e995）。`rifts=0`では消費しない＝028の乱数列を乱さない | - |

比較用に`riftTower=0`（どこでも開く）・`riftCeil=N`（帰着線N以上では開かず閉じる）・`riftBandMult=0`（深さで変わらない）を残す。

### HUD（028-final提案(3)・029-final軽微#2）

028の17行を**揺れゲージ1本＋5行**に集約した（HUDの高さ 306px → 152px）。

- **揺れゲージ（横幅いっぱい）**: 今の揺れ（色は落盤しやすさ）・帰着線（白い縦線）・注意線（黄）・危険線（赤）・注意線の外の紫の帯（割れ目が開く帯）・
  下の目盛りに被ダメ倍率（×2・×3・×5の揺れ）・右端に踏ん張りの点・注意線の右に開いている割れ目の残り（紫の棒）。被ダメ×2を超えると縁が赤く脈打つ
- ゲージの見出し1行: 揺れ・帰着・売値ボーナス・落盤率・踊り場（▼回廊／▼塔の圏）・割れ目（開いていれば「割れ目N（掘ると揺れ−10）」、開く状態なら「割れ目N%/t ¥売値」）・粘った秒数（⌛）
- その下に5行: 積荷と被ダメ倍率／HP・ATK・防具・お金／昼夜と今夜の予告／建設費といちばん近い塔／記録。最後にキーの一覧（10px）
- **文字は幅に収まるまでフォントを縮める**（`fitText`、最小7px）。キャンバス幅560pxでも見出しの右端が欠けない
- 割れ目のマスは紫に脈打つ枠と、売値・閉じるまでの秒

## タッチ操作の想定（iPad/Android、Capacitor移植時）

- 移動・攻撃・ダッシュ・建設・塔の操作は028と同じ（仮想スティック＋アクションボタン、塔パネルの長押し）
- 揺れゲージは画面上端に横長で常時表示（030で実装したゲージをそのまま上端へ移す）。被ダメ×2を超えると縁が赤く脈打ち、振動を返す
- **割れ目はタップで「そこへ向かって掘る」**（隣接なら1タップ。4秒しか無いので、スティックの往復より短い操作で取れることを優先）。
  割れ目のマスの売値と残り秒は指で隠れないようマスの上辺に出す
- 割れ目が開いた瞬間に短い弱い振動（踏ん張りの強い振動と区別する）
- 塔の見張りの外では割れ目が開かないことを、ゲージの紫の帯を灰色にして示す（キーボード版は見出しの割れ目の表示が消える）

### 開発中の観察（初版の設計判断、20〜40シード）

- 029の値のまま（どこでも開く・売値20・確率0.04）では、注意線の外に長く居る攻勢ほど割れ目を取り、bareの稼ぎが+70%、遅延0でbareが5戦略に過半数で勝った（028は1〜2）
- 塔の見張りの下に結ぶと（`riftTower=1`）bareは割れ目を持たず、遅延0で0〜1戦略に。取り分が15%と低かったので売値35・確率0.08で3割強に合わせた
- 帰着線45で閉じる案・深さで変わらない売値・抜ける揺れ15はどれも悪かった（表はv1レビュー）
- 本計測（160シード）の結果と、新規重大「p01が全戦略に勝つ」は[v1レビュー](../../reviews/030-flagship-ventward-v1.md)

## AI評価の観点

- **合格線A: 「bareが過半数で勝つ相手が無い」を遅延0/3/6秒（`--delay 0/30/60`）のすべてで**（元の7戦略＋pusher）
- **合格線B: 慎重な戦略（wall・mason・spire・spireAll・weave・p02）の3秒の罰が−8%以内**
- `--preset 028`で028の数字（既定・遅延の表）を同じボットで再現して並べる
- 塔の見張りが積荷の半分を届けることが「迷いの免除」（029の籠と同じ）になっていないかを、遅延ありの対比較で見る（p01・pusherの遅延の罰）
- 固定閾値の掃引（`--sweepAll`、T30〜75）で山の位置に加え「山から+40の下り」（T30→T70相当）と「台地の幅（山の95%以上の閾値の範囲）」を記録する
- 割れ目の取り分（換金した稼ぎのうち割れ目の分）が3〜4割に収まるか
- ブラウザ: 単一HTML＋検証ボットでヘッドレスと一致するか、割れ目が開いた画面とHUDの集約（狭い画面で欠けない）をスクリーンショットで確認する
