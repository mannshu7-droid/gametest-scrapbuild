## サイクル27の狙い

020-final（サイクル26総括）が発見した最大の構造課題は、**「拠点の防衛投資（タレット・壁・鑑定）が、実際に死ぬ場面に届いていない」**ことだった。
防衛系の死亡の94%は夜のフィールドで起き、拠点内での死亡はわずか7.5%。拠点をどれだけ強化しても、主人公が日没までに
帰り切れなければ死ぬ。009-ironmarch以来の**戦闘単体プロトタイプ**として、この「日没までに帰る/帰れない」という
緊張そのものを主題に切り出し、**戦闘だけ**（採掘・建築は入れない）で以下2点を検証する。

1. **帰還の巧拙（逃走・ダッシュ・囮・迎撃地点の選択）がスキルとして面白いか**
2. **撤退の準備（退路の確保・帰路の投資）が悩ましい選択になるか**

021で確立できれば、022以降で本命ゲームの拠点防衛へ「帰還ルートの安全度に効く設備」として統合する
（017/019で単体確立→flagship統合の順が成功した手順を踏襲）。

## コアファン仮説（1行）

> このゲームは「**日没までに拠点へ帰り切れるか**というタイムプレッシャーの中で、押し込む(前進で稼ぐ)か
> 退く(安全に帰る)かを毎回判断し、退路そのもの（ルート・ダッシュ・囮・強化）に投資する」ことが面白いはず。

## コンセプト

- ジャンル / 視点: 2D横スクロール風、実質1次元（拠点からの距離のみで進行を表現する数直線ワールド）
- プレイ時間の想定: 1セッション15〜25分（1日＝1往復、15日生存で区切り）
- 参考にするゲーム: 7 Days to Die（夜の帰投プレッシャー）、Project Zomboid（対面戦闘の緊張）、
  009-ironmarch（EVヒント・危険度公開のパターン踏襲）

## コアループ

1. **拠点（distance=0）で仕度**: 前日までに稼いだ資金で強化（攻撃力・最大HP・ダッシュ枠・囮枠・日照時間延長）や
   囮の補充を行う。拠点内は常に安全（敵は侵入しない、HPは全回復）
2. **前進（押し込み）**: `advance` で拠点から離れる（distanceが増える）。離れるほどレイダーとの遭遇が増えるが、
   撃破報酬も距離を稼ぐほど効率的（襲ってくるレイダーを倒すだけで資金が貯まる）
3. **判断（帰るか押すか）**: 残り日照（`daylightRemaining`）と現在distanceから「このまま真っ直ぐ帰った場合の
   余裕（`returnMargin`）」が常時公開される。マージンが減ってきたら退却を始める
4. **退却**: `retreat` で拠点へ戻る。退却開始時（またはいつでも1回）に**帰路**を`direct`（近道・敵が多い）か
   `detour`（遠回り・敵が少ない）から選べる。ダッシュで距離を稼ぐ、囮でレイダーの足止めをする、などで
   帰路の危険を管理する
5. **日没**: `daylightRemaining` が0になると夜が来る。まだ拠点の外にいる場合、レイダーの速度・攻撃力が
   跳ね上がり、非常に危険になる（020-finalの「夜のフィールドで死ぬ」構造をそのまま再現し、対策を検証する）
6. **帰投**: distance=0に到達すると当日は生存確定。全回復・資金確定・翌日へ（レイダーは日ごとに強化される）
7. 15日生存で勝利（`over=true, won=true`）。HP0で死亡（`over=true, won=false`）。死亡時は「どの局面で
   死んだか」（前進中/退却中(昼)/退却中(夜)）を`metrics.deathPhase`に記録する（020-finalのLearningsで
   確立した死亡直前状況メトリクスを最初から標準搭載）

## システム仕様

### ワールド

- 1次元の「拠点からの距離」（distance、0〜220、0=拠点）のみでプレイヤー・敵の位置を表現する
  （render用にy座標も持たせるが見た目の分散だけで、戦闘判定には使わない）
- 拠点（distance=0）は常に安全地帯: 敵は侵入せず、到達すると全回復し当日の帰投が確定する
- 距離が離れるほど（＝日を重ねるほど）レイダーが強化される（`day`に比例したスケーリング）

### プレイヤー（能力・リソース・成長）

| 項目 | 初期値 | 説明 |
|---|---|---|
| HP | 100/100 | 拠点到達で全回復 |
| 攻撃力 atk | 10 | `attack`アクションのダメージ |
| 移動速度 | 1/tick | `advance`/`retreat`の基本移動量 |
| ダッシュ | 枠2、+3移動量、再チャージ120tick/枠 | `dash`で瞬間的に距離を稼ぐ・詰める |
| 囮 flare | 枠1（拠点で補充制、自然回復なし） | 半径12以内のレイダーをEXITTICKS間ひるませる |
| 日照時間 daylightMax | 260tick | distance>0の間だけ消費。拠点で0にリセット |
| 資金 money | 0 | レイダー撃破・強化購入の元手 |

**強化（拠点内・distance=0のみ購入可）**:

| 強化 | コスト（Lv0基準、Lvごとに増加） | 効果 |
|---|---|---|
| atk | 15+Lv×10 | 攻撃力+3 |
| maxHp | 15+Lv×10 | 最大HP+20（即回復も） |
| maxDash | 20+Lv×15 | ダッシュ最大枠+1 |
| maxFlare | 20+Lv×15 | 囮最大枠+1 |
| daylight | 25+Lv×18 | 日照時間の最大値+25tick（＝**帰路への投資**の中核） |
| 囮補充 | 不足分×(8+day) | 囮を最大枠まで補充 |

### 敵（種類・行動・スポーン）

- 単一種「レイダー」。プレイヤーより常に拠点から遠い位置（distance+6〜14）にスポーンし、
  プレイヤーのdistanceへ向かって接近する（前進中は「奥から迎え撃つ」、退却中は「追ってくる」を
  同じロジックで自然に表現する）
- ステータスは`day`に比例して強化（`hp=18+day*4`, `atk=4+day*0.6`, 速度0.9/tick、射程2）
- **夜間（`daylightRemaining<=0`）は速度×1.5・攻撃力×2.0・出現間隔短縮**。020-finalで判明した
  「夜のフィールドでの死」を意図的に再現し、対策（帰路投資・囮・ルート選択）が効くかを検証する対象にする
- 撃破報酬は`5+day`（資金源）

### 経済（資源の入手と使い道の対応表）

| 入手 | 使い道 |
|---|---|
| レイダー撃破報酬 | atk/maxHp/maxDash/maxFlare/daylight強化、囮補充 |

単一の資金源だが、使い道は5系統（攻撃・耐久・機動・囮・帰路マージン）に分かれ、
「今日装備を強めるか、来週の帰路マージンを厚くするか」という悩ましさを作る。

### ルート選択（帰路の投資・退路の確保）

- distance>0の間、1日1回`chooseRoute`で`direct`（-10distance即時短縮、敵出現間隔0.6倍＝危険）か
  `detour`（+15distance、敵出現間隔1.6倍・敵速度0.85倍＝安全）を選べる（未選択なら補正なし）
- 常時、`returnMargin`（`daylightRemaining - distance/移動速度`の概算）と`retreatRiskLevel`
  （safe/caution/danger）、簡易な`routeRecommended`（direct/detourのどちらが期待マージンで有利か）を
  公開する（003/011の安全マージン公開、009のEVヒントの系譜）

### 勝利/敗北条件

- **勝利**: 15日（`DAYS_GOAL`）生存すると`over=true, won=true`
- **敗北**: HPが0になると`over=true, won=false`。`metrics.deathPhase`に
  `push`（前進中）/`retreat-day`（昼の退却中）/`retreat-night`（夜の退却中）を記録する

## タッチ操作の想定（iPad/Android・Capacitor移植前提）

実装はキーボードでよいが、仕様として以下を想定する（005〜020までの「4方向パッド」相当の反省を踏まえ、
本ゲームは1次元移動のため方向パッドは不要）:

- 画面下部に前進/後退のスライダー的な2ボタン（左半分=退却、右半分=前進の大きなタップ領域）
- 攻撃ボタン（1つ、範囲内の最も近い敵を自動対象）
- ダッシュボタン×2（前進ダッシュ/後退ダッシュ、枠数をボタン上にバッジ表示）
- 囮ボタン（1つ、枠数バッジ表示）
- ルート選択は退却開始時にモーダルで`direct`/`detour`の2択カードを表示しタップで選択
- 拠点内（distance=0）ではショップUIに切り替わり、5項目＋囮補充をタップで購入（価格・効果を常時表示）
- 全てシングルタップの離散操作で、連続量の操作（スワイプ量に応じた移動など）は使わない（AIP規約準拠）

## バランス初期値

上記「プレイヤー」「敵」の表の数値を初期値とし、`npm run simulate`で検証する。特に重視する指標:

- `returnMargin`が負に転落してから実際に帰投できた/できなかった割合（帰還判断の意味検証）
- `direct`/`detour`それぞれを選んだ場合のavgScore・死亡率・deathPhase内訳の差（ルート選択の意味検証）
- daylight強化への投資有無で`deathPhase='retreat-night'`の発生率がどう変わるか
  （＝「帰路投資が夜の死を減らすか」という021の核心的な検証）

## AI評価の観点

- 「常に全力前進し続けるだけ」で強い場合、帰還判断というスキルが不要になっていないか
  （＝退却しない戦略がscoreで勝ってしまわないか）
- 「daylight強化を一切買わない」戦略と「daylight最優先」戦略で、`retreat-night`死亡率に有意差が出るか
  （020-finalの構造課題「投資が死ぬ場面に届くか」への直接の回答になる）
- `direct`/`detour`の選択が、040-linkmark同様に「実は片方が支配的」になっていないか
  （複数指標が同じ向きに揃うかで判定する。020-finalのLearnings参照）
- 囮(`decoy`)が実際に使われる場面がどれだけあるか（発火回数を数える。016タレット制圧射撃の教訓＝
  「効果を足す前に発火回数を数える」を踏襲）
- 死亡直前状況（`deathPhase`）の内訳が実際に取得でき、「夜の退却中に死ぬ」が支配的因子になるかを確認する
