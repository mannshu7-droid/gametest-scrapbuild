## コアファン仮説（1行）

> 「掘って進むか、資材とお金を払って迂回するか」を採掘のたびに選べ、さらに「戦って押し切るか、
> 一時的な防壁を築いて安全を確保するか」を戦闘のたびに選べる———採掘・戦闘それぞれに建築という
> 「第三の選択肢」が常に存在することで、005で単調だった「掘る/戦う」の二択が「掘る/建てて迂回する/戦う/建てて凌ぐ」
> の四択に広がり、意思決定の悩ましさ（002〜005共通の積み残し課題）が本質的に解消されるはず。

## コンセプト

- ジャンル / 視点: 縦シャフト採掘 + リアルタイム近接戦闘 + 最小構成の設置建築（2Dトップダウン、003/005と同じ縦シャフト視点）
- プレイ時間の想定: 1セッション10〜20分（005を踏襲）
- 参考にするゲーム: 7 Days to Die（採掘・戦闘・建築の併存という本命ゲームそのものの狙い）、
  Terraria（掘れない壁を足場で迂回する感覚）、および本リポジトリの002/003/004/005

## コアループ

```
地上(常設ショップ)で採掘・戦闘・建築カテゴリを強化
  → 坑道を掘り進む（鉱石獲得、掘削音が敵を誘発）。掘れない/掘りたくない硬いタイルに当たったら
    「支保工（プロップ）」を設置して迂回することもできる（ドリル威力への投資を節約する代わりに金を払う）
  → 敵と接敵したら、正面から戦うか、退路に支保工でバリケードを築いて時間を稼ぐかを選べる
  → 燃料・HPが危険域に入る前に地上へ帰還
  → 鉱石を売却し、稼いだ金で採掘/戦闘/建築の3カテゴリのどれに投資するか選ぶ
  → さらに深く（深さに理論上の上限はなく、詰まるまで/力尽きるまで続く）
```

## タッチ操作の想定（iPad/Android移植時。今回の実装はキーボードでよい）

- 移動・採掘: 画面下部の仮想8方向パッド（005と同じ。既に掘った床なら移動、未採掘タイルなら採掘）
- 攻撃 / スキル: 独立ボタン2つ（005を踏襲）
- 緊急離脱（dash）: 独立ボタン、クールダウン中はグレーアウト
- **設置（build）**: 新規の第4ボタン。押すと直前に向いていた方向へ支保工を設置する
  （対象が未採掘タイルなら迂回用の橋、既に掘った床ならバリケード、と自動判別。タップ操作は1つで済む）
- 帰還判断支援・脅威レベルHUDは005を踏襲。加えて「設置コスト」「支保工クールダウン」を常時表示
- ショップ: 地上フェーズ時のみ画面全体にカテゴリ一覧を表示、タップで購入（PC版のキー1〜9に対応。9番目が建築枠）

## システム仕様

### ワールド

- 縦シャフト構造（003/005を踏襲）: 幅 `W=16`、深さ `H=161`（y=0が地上、y=1〜160が8バンド×20マス）
- タイル種別: `FLOOR` / `DIRT` / `ROCK` / `ORE_COPPER` / `ORE_IRON` / `ORE_GOLD`（005と同一）に加え、
  新規 `PROP`（支保工。プレイヤーが設置した構造物。移動威力に関係なく常に通行可能）
- `PROP` には耐久値（propHp）がある。プレイヤーの移動では消耗しないが、敵はこれを壊さないと通過できない
- 敵は「既に掘った床(FLOOR)」だけを移動できる。`PROP` は敵にとって通行不可（005のROCK同等の扱い）

### プレイヤー（能力・リソース・成長）

- HP・燃料・所持金・積載・採掘威力・攻撃力・攻撃CD・スキル・掘削音・estFuelToReturn・dash: 005を全て踏襲
- **build（設置）**: 新規アクション。向いている方向の隣接タイル1マスに支保工を設置する
  - 対象が未採掘タイル（DIRT/ROCK/ORE_*）の場合: **迂回橋**。採掘威力を満たさなくても即座にそのマスを
    `PROP`（通行可）に変える。ただし鉱石だった場合はその鉱石の価値を得られない（掘るか迂回するかの本質的トレードオフ）
  - 対象が既に掘った床(FLOOR)で敵・プレイヤーが不在の場合: **バリケード**。そのマスを`PROP`にし、
    追ってくる敵の経路を塞ぐ（耐久値が尽きるまで敵は通過できない）
  - 対象が範囲外・敵が乗っている・既に`PROP`の場合は不発
  - 設置ごとにクールダウンがあり連打はできない。コストは所持金で支払う（迂回橋は対象タイルの硬さ・深さに応じて
    加算、バリケードは深さのみで加算。工兵カテゴリのショップ投資でコスト低減・耐久値上昇の両方が伸びる）

### 敵（種類・行動・スポーン）

- 種別・湧き確率・BFS移動・囲みスロット割当ては005を完全に踏襲
- 追加: 敵は自分と目標（プレイヤー）を結ぶ経路が`FLOOR`だけでは存在しない（＝`PROP`に塞がれている）場合、
  隣接する`PROP`があればそれを攻撃する（プレイヤーへの攻撃と同じATK値・CDで、耐久値を削る）。
  耐久値が尽きると`PROP`は`FLOOR`に戻り、敵は通過できるようになる

### 経済（資源の入手と使い道の対応表）

005の常設ショップ8項目（drill/capacity/fuel/atk/hp/atkspeed/skill/muffler）に加え、新規カテゴリを追加する。

| カテゴリ | 項目 | 効果 | 備考 |
|---|---|---|---|
| 採掘 | drill / capacity / fuel | 005と同一 | |
| 戦闘 | atk / hp / atkspeed / skill | 005と同一 | |
| 共通 | muffler | 005と同一 | |
| **建築（新規）** | engineering（工兵術） | 設置コスト-15%/レベル（下限-60%）、支保工の耐久値+15/レベル | 採掘・戦闘どちらにも波及する橋渡しカテゴリ（mufflerと対になる建築側の橋渡し項目） |

### 勝利/敗北条件

- 敗北: HPが0になる（ゲームオーバー）。005と同様、単一の到達目標では終了しない
  （深さ40・80・120…のマイルストーンボーナスは中間報酬であり、プレイは死ぬかティック上限まで続く）
- スコア = 所持金+積載中価値 + maxDepth×係数 + 撃破数×係数（005を踏襲。設置関連の得点化は今回は行わない
  ——「建てること自体」ではなく「建てて何ができたか（深さ・生存・稼ぎ）」で評価するため）

### v2で調整したバランス値（reviews/006-combat-mining-building-ironkeep-v1.md 指摘#2〜#4対応）

v1は全80ラン（20シード×4戦略）で死亡0件という「安全すぎるバランス」だった。005から継承した値のうち
敵の湧き頻度・強さ・地上回復・迂回橋コストを以下のとおり調整し、死亡が現実的に起こりうる（＝バリケード/dashが
「決定的な救済」になりうる）水準へ引き上げた。

| 項目 | v1値 | v2値 | 備考 |
|---|---|---|---|
| SURFACE_HP_REGEN（地上HP回復） | 3/tick | 2/tick | 帰還のたびの回復を鈍らせる |
| SPAWN_BASE（湧き確率基礎値） | 0.003 | 0.0042 | チョークポイント遭遇頻度を上げる |
| bandMult係数（敵湧き頻度の深さ倍率） | `1+band×0.35` | `1+band×0.5` | 深部の湧き頻度を引き上げる |
| depthMult係数（敵HP/ATKの深さ倍率） | `1+band×0.2` | `1+band×0.25` | 深部の敵を強化 |
| enemyCap（同時湧き上限） | `min(2+floor(band/3),6)` | `min(2+floor(band/2),8)` | 深部で複数体同時接敵を増やしバリケードの必要性を作る |
| BRIDGE_BASE_COST | 10 | 12 | |
| BRIDGE_TIER_COST | 6 | 7 | |
| BRIDGE_BAND_COST | 2 | 4 | 連続する壁を迂回橋だけで踏破する総コストを引き上げ、drill投資との差をつける |

20シード（1〜20）×4戦略の再検証結果（死亡率）: mining-first 2/20・combat-first 0/20・balanced 0/20・
bridge-reliant 0/20（v1は全戦略0/20）。バリケード建築を無効化したA/Bシミュレーションでは
mining-firstの死亡が2/20→8/20へ増加（他戦略は変化なし）し、バリケードがmining-first戦略（戦闘系ステータス
投資が後回しになりやすい）に対して明確に死亡を防ぐ効果を持つことを確認した。迂回橋コスト引き上げにより
bridge-reliantのavgMaxDepthはmining-first比で-3.4（40.5 vs 43.9）、avgUpgradesBoughtは-2.6（2.9 vs 5.5）と
「迂回橋はdrill投資よりトータルで高くつく」という設計意図が数値面でも表れるようになった。

### v3（3回目 FIX only）で検討し、変更を見送った項目

v2レビュー（reviews/006-combat-mining-building-ironkeep-v2.md）の残課題2点について、コード変更の要否を
検証した結果、いずれも構造的に説明できる意図通りの挙動と判断し、バランス値の変更は行わなかった。

1. **efficiency優先プレイで迂回橋・バリケードの使用機会が少ない件**: `BUILD_COOLDOWN=10tick`（設置後の
   硬直）に対し、`digTicksFor`は採掘威力が要求値ちょうどの場合でも土2/銅3/岩4/鉄5/金6tickと、いずれも
   建築のクールダウンより短い（採掘威力を要求値以上に投資していればさらに短縮される）。つまり
   **採掘威力が足りている限り、迂回橋は「掘るより遅く、かつ有料」で常に採掘に劣後する**——これは
   「迂回橋はdrill投資の代替（保険）であり、drill投資済みの相手にとっての近道ではない」という設計意図
   そのものであり、バグではない。20シード再検証でも `avgBridges` はdrill非投資のbridge-reliant戦略が1.8、
   drill投資する他3戦略は0.1〜0.7と明確に相関しており（[headless/simulate.ts](../../games/006-combat-mining-building-ironkeep/headless/simulate.ts)参照）、
   数値面でもこの設計意図どおりの分布になっていることを確認した
2. **死亡がmining-first戦略に偏っている件**: v2のA/Bテスト（バリケード無効化で該当戦略のみ死亡2/20→8/20）
   により、バリケードは「戦闘系ステータス投資を後回しにするmining-first戦略」に対して明確に機能する
   保険として設計どおりに働いていることを既に確認済み。死亡がこの戦略に偏っていること自体が
   「バリケードが必要とされる状況を作れている」証左であり、これを均そうとする（＝mining-firstの死亡率を
   下げる）調整はむしろバリケードの存在意義を薄める方向に働く。現状維持が妥当と判断した

上記2点はいずれも「軽微・費用対効果を見て判断すること（無理に手を入れず現状維持もありうる）」と
v2レビューで明記されていた項目であり、本ラウンドでは`npm run build`/`npm run simulate`（20シード×4戦略）で
v2と完全に同一の結果（死亡2/80、avgBridges/avgBarricades等すべて一致）が再現することを確認したのみで、
`src/core/game.ts`・`headless/simulate.ts`ともに変更していない。

### 実装前に決定した設計判断（005最終レビューの提案3への対応）

002〜005で4要素連続で再発した「進行を止める壁を他の項目と同列優先度で並べると投資が後回しになり続ける」
問題に対し、006では**壁自体を後追いで緩和するのではなく、壁を迂回する構造的な手段（迂回橋）を最初から
用意する**という設計判断を実装前に確定させた。これにより「drillに投資しない」という選択が「詰む」ではなく
「都度お金を払って迂回する（＝トータルではdrillに投資するより高くつくが、詰まない）」という有効な代替戦略になり、
後付け修正が既存仕様（進捗リセット・指数ペナルティ等）と衝突して新種のソフトロックを生んだ005 v3の失敗を回避する。

## AI評価の観点

- **迂回橋は実際に使われるか**: drill投資を絞った戦略が、迂回橋によって005のcombat-first(maxDepth=40で頭打ち)
  よりも深く進めるようになるか。「壁を同列優先度で後回しにし続けると詰む」という002〜005共通パターンが
  006では解消されているかを最重要observationとして計測する
- **バリケードは実際に使われ、意味を持つか**: 退路のチョークポイントで、dashだけでなくバリケードも
  選択肢として機能しているか（005ではdashがヘッドレスシミュレーションで一度も使われなかった。
  バリケードも同様に使われないだけの機能になっていないか）
- 迂回橋で鉱石を捨てる判断が「悩ましい」トレードオフとして成立しているか（自明な最適解に倒れていないか）
- 工兵（engineering）カテゴリが採掘・戦闘と競合する第3の投資先として実際に選ばれる余地があるか
  （常に劣後する投資にならないか）
- 敵がバリケードを壊すまでの時間が「意味のある遅延」になっているか（一瞬で壊れる・逆に無敵に近いの両極端を避ける）
