## 本レビューの位置づけ

サイクル7 finalで本命ゲームの統合実装は完成度に達したと判定されたため、サイクル8は新しいゲーム番号を
切らず`games/008-flagship-frontierhold`をそのまま磨き上げる。008finalが次サイクルへの提案として
挙げた3点（(1)危険度UIヒント`combatRiskLevel`に反応する適応型ボット戦略の追加検証、(2)マップ最深部
到達時の区切り・報酬演出、(3)mining-first戦略の初見詰みやすさの再検討）はいずれも「新要素の追加」
ではなく「既存システムの検証手法・伝達方法の改善」であり、CLAUDE.mdの「コンテンツの水増しはしない」
方針と整合する。本レビューは通常の1回目（BUILD+REVIEW）に相当する回として、この3課題への対応を
両ペルソナで評価する。

## 実施した対応（詳細はspec.md参照）

1. **適応型ボット戦略**（`headless/simulate.ts`）: `mining-first-adaptive`/`combat-first-adaptive`/
   `balanced-adaptive`を新規追加。`combatRiskLevel`が`danger`のとき購入優先度でhp/atkを繰り上げ、
   低HPを待たずに自主的に帰還する
2. **最深部到達の区切り・報酬演出**（`src/core/game.ts`/`src/render/renderer.ts`）: y=160到達時に
   一度だけ+300money・HUDバナー表示（`Metrics.bottomReached`/`GameState.bottomReachedBanner`）
3. **初見詰みやすさ対策**（同上）: `combatRiskLevel`が初めてsafe以外になった瞬間に一度だけ強調バナー
   表示（`GameState.firstRiskWarningBanner`）。バランス数値・ボットロジックには非接続

## 定量評価（ヘッドレスシミュレーション、20シード×8戦略）

`npm run simulate -- --seeds 1,2,...,20 --maxTicks 20000`（詳細な表はspec.md参照）:

- **combat-first・bridge-reliant・balanced-no-outpost（最深部に到達しない3戦略）はfinal時点と完全に
  ゼロ差分。** 今回の3つの追加が既存の固定戦略・既存バランスへ副作用を与えていないことを裏付ける
- **mining-first-adaptiveは死亡9/20→6/20（-33%）に改善**（引き換えにavgMaxDepth78.8→69.0・
  avgScore528.2→446.6）。balanced-adaptiveも死亡2/20→1/20に改善。combat-first-adaptiveはほぼ無変化
  （元の戦略が既にsafe/caution圏内のため適応ロジックが介入する場面が少ない）
- mining-first/balancedのavgScore等がfinalからわずかに変化したのは、最深部到達時の+300moneyボーナス
  （3/20・1/20のシードで発生）が以降の購買判断・行動系列を変えた結果であり、意図した仕様どおり

## 定性評価（AIブラウザ実プレイ、window.__AIP__経由）

`npm run dev`（port 5180）を起動し、v2ボットロジック（drill初回購入特例込み）をJS移植して
P01(seed301)/P02(seed302)を6000tickフル実行した。まず固定戦略でfinal版と完全に同一の結果
（P01: tick4524死亡・maxDepth85・score447、P02: combat-first相当でfinalHp70/maxDepth79/score447）を
再現し、決定論と回帰の不在を確認した上で、適応型戦略との比較を行った。

### P01（野望型）視点 — seed301、mining-first(-adaptive)優先度

| 指標 | 固定（mining-first、final再現） | 適応型（mining-first-adaptive） |
|---|---|---|
| 生死 | **tick4524で死亡** | **6000tick完走** |
| 最終HP | 0/100 | 41/140 |
| maxHp | 100（hp未投資） | 140（危険域でhpを2レベル追加購入） |
| maxDepth | 85 | 85 |
| score | 447 | 501 |
| combatRiskLevel推移 | tick1500以降ほぼ`danger`固定、一度もsafeへ戻らない | tick1500以降`caution`主体（`danger`は稀）、死亡なし |

**同一シード・同一初期条件で、固定戦略は008finalが記録した通りのtick4524死亡を再現し、適応型戦略は
その死亡を完全に回避した。** これは008finalが「情報を見せる効果は確認できたが、見た情報で実際に
行動を変える効果は現在の検証手法（固定優先度のヘッドレスbot・そのブラウザ移植）では原理的に
検証できない」と留保していた仮説に対する、初めての肯定的な定量結果である。適応型戦略は「深く速く
潜れる」というdrill優先ビルドの利点を一部犠牲にして生存を選んでおり、003finalが確立した
「ビルド次第で生死が分かれる」設計哲学とも整合する形で、「危険を感じたら安全側に倒す」という
判断が生存とリターンの明示的なトレードオフとして機能した。

- **A1経済・A2成長実感（P01最重要軸）**: 4/5（drillPowerは固定と同じく1→4まで成長。適応型は
  さらにhpも1→3まで育ち、「危険を感じて生存力に投資する」という新しい成長の選択肢が機能した）
- **N2徒労（P01致命トリガー）の該当性**: 固定戦略の死亡はscore447が残るため徒労ではなく
  「警告を無視した結果の死」（008final同様の解釈）。適応型は死なずに完走しさらに高いscore(501)を
  得ており、致命トリガーには一切該当しない
- P01自身は「達人クイック作戦」のようなハイリスク・ハイリターンな仮説検証を好む性格でもあるため、
  「危険ヒントに従って手堅く完走する」適応型の結果を見て「それはそれで悪くないが、リスクを取って
  死んだ固定戦略の方が"物語"としては面白い」と評価する可能性がある。**両方の結果が同じ画面で
  比較できること自体が、P01にとってのA5仮説検証（ビルド戦略の比較実験）の材料になる**

### P02（あき型）視点 — seed302、combat-first(-adaptive)優先度

| 指標 | 固定（combat-first） | 適応型（combat-first-adaptive） |
|---|---|---|
| 生死 | 6000tick完走 | 6000tick完走 |
| 最終HP | 70/140 | 70/140（完全一致） |
| maxDepth | 79 | 79（完全一致） |
| score | 447 | 447（完全一致） |

**固定・適応型で完全に同一の結果になった。** P02のビルド（atk/hp優先）はセッション全体で
combatRiskLevelが一度も`danger`にならなかったため、適応ロジックが介入する場面自体が発生しなかった。
これは「安全なビルドには何も起きない」という期待通りの結果であり、適応ロジックが安全なプレイに
余計な干渉（不要な足踏み等）をしないことを裏付ける良い副産物である。

- **A6目標構造・マイルストーン（P02最重要軸）**: 4/5（final同水準）。適応ロジックの追加が
  既存の「前線基地で少し深く進める」体験を損なっていないことを確認できた
- **A9世界の一貫性**: P02は今回、危険度ヒント自体が一度も強く発火しなかったビルドで完走したため、
  「危険を煽られずに安心して物色できた」という側面もそれ自体一貫性のある体験として評価できる

## 判定

**FIX**（3課題とも一定の成果を確認したが、追加の詰めが残る）

理由:

- 008finalの最優先課題（適応型ボットがUIヒントに反応して行動を変えられるか）は、mining-first-adaptive
  が同一シードで固定戦略の死亡を完全に回避するという明確な肯定的結果を得た。これは008finalが
  「検証不能」と留保していた仮説への初めての定量的な答えである
- 最深部到達演出・初回警告バナーはいずれもヘッドレス・ブラウザAIP双方で正しく動作することを確認し、
  既存の固定戦略・バランス数値への副作用がゼロであることも確認した
- 一方で、適応型戦略のパラメータ（hp/atk繰り上げの閾値、danger時の即時撤退の是非）はまだ
  第一版であり、combat-first-adaptiveのように介入機会が少なすぎるケースの扱いや、mining-first-adaptive
  のavgScore低下が「安全すぎる」方向への振れすぎでないかは、2回目（FIX+REVIEW）で詰める

## Learnings（次のFIX・次サイクルに持ち越す学び）

- **UIヒント（combatRiskLevel）が実プレイヤーの行動を変える効果は、「ヒントを参照して動的に
  優先度を変える適応型ボット」を用意すれば定量的に検証できる。** 008finalが指摘した検証手法の
  構造的な盲点は、固定優先度ボットに一枚レイヤーを足すだけで解消できた。今後、UI/UXを軸にした
  施策（警告・ヒント表示等）を評価する際は、最初から「ヒントを無視する固定戦略」と「ヒントに従う
  適応戦略」の両方をA/Bで用意することを標準手順にすべき
- **恒久建築物・最深部到達など「一度きりのイベント」に伴う報酬（money等）は、以降の購買判断の
  分岐点をわずかに変え、行動系列全体に影響することがある。** 副作用の有無を確認する際は「その
  イベントが発生しない戦略・シードで完全にゼロ差分か」を必ず確認し、「発生する戦略でわずかに
  数値が変わること」自体は意図した仕様であり回帰ではないと区別する必要がある（今回のmining-first/
  balancedのavgScore変化がその例）
- 「情報を見せるだけのUIヒント」（008 v3の`combatRiskLevel`）は、実際に効果を持つことが今回
  実証されたが、それは「ヒントを見て行動を変える主体」が存在する場合に限られる。実プレイヤーは
  当然ヒントを見て行動を変えられるが、それを事前にどれだけ正確に模擬できるかが今後のヘッドレス
  検証の精度を左右する
